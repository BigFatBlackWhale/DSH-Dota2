口径与已知边界（坦诚说明 · 请务必先读）

① 时间口径：0:00 = 号角（combat_log gamestate value=5 的 t_cle）； 出门 = −1:30（实测初始金 600 事件恰在 −1:29.9）。所有展示时刻都是这条轴。 entity_snapshots / dems/db 的 CD 事件是回放钟（tick/30）→ 经 analysis/timebase.py 的暂停感知折算（本场暂停 0.0s）。

② ±10s 明细全部来自 combat_log（4 类：modifier 按 attacker/target 分给出/收到、 damage 同理）。窗口 = 当前播放时刻 ±10s（owner 默认）。逐条内嵌、无采样丢失； "折叠连续同项"只是在显示层把同名称/同类别/同数值且时间相邻(≤1.2s)的条目并成一行（括号里是区间精确条数）。

③ 技能 CD来自 dems/db/<league>/<match>.db 的 ability_cd_start/end + ability_known/learn + item_cd_* + item_known （combat_log 版库里没有这些：CD 是实体派生、不是 combat 条目）。 不需要任何冷却常量表 —— properties.remaining 就是实体 m_fCooldown 的 实际剩余冷却秒（含等级/天赋/减CD），区间 = [cd_start, cd_end]（有 end 用真实 end）。 TP 是充能制、库内无 CD/充能事件 → 只显示"使用时刻 + 次数"（如实标注，不硬造三态）。

④ 胜率是派生模型，不是 combat log：P(天辉胜 | 净值差, 经验差, t) 逻辑回归， 在 — 场上拟合，按 match 划分训练/测试防泄漏；特征只用 t 时刻可观测的量， 绝不使用最终结果。标签 = 远古被摧毁（badguys_fort 死→天辉胜）。验证：—。 它是"历史上处于这种局面的队最终赢了多少"的统计映射，不是这场比赛的预测。 模型形态 = 分时间桶的逻辑回归 + 桶间系数线性插值（对 t 连续）；分桶 AUC 见上。 ⚠️ 经济差与经验差实测正相关 r=0.52 → 单个系数的符号不具解释意义， 模型只在两者联合的实测分布上有意义（页面喂的就是实测值）。

⑤ 两个"经济差"是两套源，别混： 净值差（m_iNetWorth）= 标准经济差（现金+装备，非 combat log，项目内对账 OpenDota 0.000%） —— 已由 owner 定案为本页主显口径； combat-log 累加= 累计获取金币差（已按 gold_reason=1 扣死亡损失； 但买装备/消耗品不减 → 与净值差会随比赛拉大，实测本场末秒两者差 —）。 胜率模型用的是净值差口径。

⑥ 经验差只有 combat-log 一条源（库内无经验快照）→ 无法交叉校验，仅作参考。

⑦ 正反补= death 条目里 attacker 为英雄、target 为线上兵；敌方兵=正补、己方兵=反补。 assist_players 的值是头部玩家索引且含击杀者本人（已剔除）。

⑧ 位置是解析层 1Hz 采样（偶有缺秒）→ 页面按"沿用上一秒"补齐（无位置则该英雄不画）。
